# R351独立代码审查与修复

审查者：独立Luna子代理（按项目路由max reasoning）。范围：共享模块、RAM加载/训练/评估、TSRS nnU-Net wrapper、overlap预训练及运行协议。

## 已修复的阻断项

1. RAM初始化不一致：旧R332按3个成员一组计算，新模块最初按2个；TF32下最大logit差0.001414，虽当次阈值mask相同仍未通过身份检查。诊断确认chunk=3或关闭TF32均差0；采用与旧模型一致的chunk=3，不放宽容忍。第二次真实审计2例input/logit差均为0，梯度检查通过。首次失败审计原件保留。
2. 距离指标遗漏失败项：官方MSD均值排除undefined样本，单看均值可能因漏预测而“改善”。新gate增加overall/overlap/pair距离失败率不得上升，overlap DSC/NSD、pair NSD不得下降，主MSD需相对原生下降至少5%。反例测试确保MSD改善但fail上升时拒绝。
3. RAM完整划分加入425/69强制断言，audit的2/2显式隔离。

## 已核对

- 输入适配器的梯度可以穿过冻结nnU-Net；未误用no_grad切断。
- TSRS单通道和RAM14通道使用同一个逐成员输出模块，无推理GT输入。
- RAM增强禁用，不再发生图像/标签与先验错位。
- TSRS标签不支持投影多重归属，真实overlap监督有效性为unknown；迁移先验的预测不伪装为GT。
- overlap先验6轮train425/val69完成；按预设val BCE选择checkpoint，未使用test。
- TSRS真实梯度审计及2轮训练/96例完整推理通过，显存约14.2GB，无OOM。
- 统一固定seam ROI只由先验+GT背景+valid定义，不随被评模型输出变化。

## 结论与限制

代码允许进入RAM两轮pilot；最终可用性必须由完整指标及gate决定。FP32内存风险由真实batch验证，不能只据语法检查放行。

TSRS从R350成熟模型继续，RAM从R332成熟模型继续；原生R202/R325是独立对照，不是初始化。报告必须同时列出相对原生和相对成熟anchor的变化，不把全部历史收益归因于本轮新增模块。源哈希由独立provenance快照补齐。

## 输出正增量保护诊断的补充审查

`(1-s)^2+s*o`在s/o∈[0,1]时位于[0,1]，只使用图像推导的先验，不读取GT；负增量保持。6项共享模块测试通过。该诊断是在观察original-val退化后提出，属于验证集开发/方法选择，不是独立泛化证据；它只限制输出模块，不能约束输入适配器引起的所有正向变化。单独记录推理策略与原checkpoint，不宣称训练推理一致或最终test成功。
