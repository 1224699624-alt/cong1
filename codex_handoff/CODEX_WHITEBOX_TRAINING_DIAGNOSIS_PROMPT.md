## 一、先取消不必要的设计限制

1. “骨缝先验必须放输入端、重叠先验必须放输出端”只是以前试过的方案，不再是不可修改的约束。
2. 可根据内部证据调整先验的生成、表示、接入位置、注入尺度、融合方式、作用范围和可训练性。输入拼接、编码器/解码器特征融合、跳跃连接、注意力/门控、输出修正、仅作为辅助监督，都可作为有依据的候选；不是要求全部尝试。
3. 可以检查或修改 nnU-Net 内部，不把骨架当作不能观察的黑盒。不因“更容易涨点”直接换一个弱骨架，也不把大换骨架当作定位问题的替代品。
4. 不要求固定保留共享关系分支、两套独立分支、全端到端、冻结先验或某个损失组合；已有 routing、preserve、surface/volume 等也不是必须有效。根据证据决定保留、削弱、修改或作为消融关闭。
5. 若某一先验有害，可关闭它做诊断；不能为保证两个模块同时出现而掩盖负结果。后续正式保留与否取决于充分、可比的实验。
6. 允许改先验或损失，不允许改真实标签含义、伪造重叠 GT、删除不利病例、改评价口径追分。未知标注保持未知，任务本身不被偷偷替换。

当前目标：在可比条件下，整体 Dice/IoU 和必要的 Recall 守住质量要求，同时改善有明确文献或基准依据的边界、成员和重叠指标。具体可接受代价及最小有意义收益须预先确定，不事后追认。不要为了迎合“先验一定有效”而解释结果。

## 三、核心工作：沿完整训练链做白盒诊断

必须追踪：

`数据/目标 → 前向先验与特征 → 各项 loss → 原始梯度 → 权重/衰减/投影/裁剪 → optimizer 状态 → 实际参数变化 → 特征与预测变化 → 验证指标`

不能仅交一张超参数表或最后指标表。区分“训练超参数”与“实际学到的参数张量”，两者都要检查。

### 3.1 前向信息流与尺度

给出真实模块/张量图，在必要的代表性位置增加轻量 hook，记录：
- 图像、S/O、各融合点和最终输入的来源、形状、坐标、成员顺序、归一化、范围；
- 先验相对于图像/特征的量级、动态范围、稀疏性、是否退化为常数；
- 代表性编码器、瓶颈、解码器、skip 与输出层的激活统计：均值、标准差、分位数、范数、非有限比例，以及适用时的零值/饱和比例；
- 融合权重、门控值、残差幅度/符号、上限饱和比例；迭代结构的每步输出与特征重算；
- 下采样、插值、padding、左右翻转是否使窄缝或小重叠信息丢失/错位；
- 先验只改变浅层，还是能影响后续表示与输出；不能只看输入通道确实存在。

用固定训练诊断样本比较原先验、零先验和少量预先确定的空间扰动。扰动统计与最终预测一起记录；这只是输入依赖/敏感性诊断，不能把分布外扰动产生的掉点当成正式先验贡献。

不要默认某个层必须融合。若建议改接入位置，要指出原位置的信息在哪里被忽略、消失、饱和或造成错误更新，以及新位置预计改善哪一条具体路径。

### 3.2 每项 loss 的实际计算

沿实跑代码逐项核验：
- loss 作用在 source、final logits，还是中间尺度；原有深监督是否保留、权重如何计算；
- 成员正负标签、seam/overlap 支持、valid/known/padding、空目标和 reduction 分母；
- 系数、状态质量衰减、类别/区域重加权后的实际值；不要把相同名义系数视为相同有效强度；
- 基础分割、成员重叠、几何/表面/体积、preserve 等是否遗漏、重复计权、相互抵消；
- preserve 的参考来自谁、是否固定、是否与当前允许修正区域冲突；
- 对一个真实双成员像素逐通道展示目标和梯度方向，不能把“至少两成员”变成全部通道为正；
- TSRS 缺失的成员监督不能因为分支存在就被当作全零负类。

分别看正成员、负成员、有效重叠、非重叠和可信局部间隙的损失贡献；这些分解是诊断，不发展为新的主评价指标。

### 3.3 参数组与梯度路径

列出实际参数名与所属 optimizer group，核对：
- requires_grad、train/eval、detach/no_grad、optimizer 是否遗漏或重复参数；
- 新增通道、融合层、先验生成器、输出头究竟哪些可训练；
- 每组实际学习率时间序列、warmup、scheduler 调用顺序、weight decay、momentum/betas、eps；
- resume/warm start 是否恢复 optimizer、scheduler、AMP scaler、EMA 和计步；
- 梯度累积、AMP unscale、overflow 跳步和 clipping 的实际顺序；
- 未启用支路的参数/缓冲区是否被意外更新；冻结权重与 train/eval 是不同状态，需分别核验。

在同一批数据、同一参数状态和可比的随机状态下，分 loss、分模块记录：
1. 原始梯度；
2. 加权及衰减后梯度；
3. 投影/路由后梯度；
4. per-aux 与 merged cap 后梯度；
5. optimizer 实际收到的最终梯度。

记录范数、None/零/非有限比例、主要方向余弦和各处理环节的缩放量。分层/分组检查，不能只看全模型一个平均范数。

先验分支没有最终任务梯度可能是冻结策略、零初始化、真实断图或 optimizer 遗漏，必须区分；若预先选择固定先验模式，生成器无梯度本来就是预期，不应报成 bug。零初始化最初阻断某条上游任务梯度，也不自动是 bug，需看后续更新与独立监督。

### 3.4 核心要求：直接记录每次 optimizer.step 后的参数变化

不要只根据 `grad.norm()` 推测模型学了多少。

对代表性参数组记录：

`delta_theta_t = theta_after_step - theta_before_step`

至少包含：
- 参数范数、梯度范数、实际更新范数；
- 相对更新量 `||delta_theta|| / (||theta_before|| + eps)`；初始范数接近0的组单列绝对量，不把该比值夸大解读；
- 自初始化的累计偏移、实际变动元素比例、更新是否长期为零；
- 初始化快照、中途快照和最终快照的变化，以及必要的归一化缓冲区变化；
- 实际使用学习率、step 计数、AMP 是否跳过本次更新、相关 optimizer 动量/二阶矩统计；
- EMA 权重、原始训练权重与推理加载对象分别是谁。

Adam/AdamW 的真实更新不能直接用 `-lr * grad` 替代。若怀疑动量、预条件或权衰减掩盖任务信号，使用克隆的完整模型与 optimizer 状态进行同起点单步分叉，区分当前配置和只改变一项的更新；严格标为当前状态的局部实验，不假装重建了整个历史因果过程。

可以记录 `g_seg · delta_theta` 作为局部一阶诊断，但它不保证验证指标改善。参数偏移大不自动是有害漂移，偏移小不自动是无效；必须结合功能变化和实验验证。

### 3.5 训练轨迹与学习是否充分

记录真实 attempted step、成功 optimizer step、unique case、patch 与有效目标暴露；保留增强及 batch ID。检查训练/验证曲线、各参数组更新曲线、先验敏感性和标准指标随训练的变化。

不能把“2个epoch”直接理解为完整遍历两遍数据，也不能将旧200步当作收敛结论。

- 几乎无有效更新：先查接线、参数登记、量级和优化流程。
- 有更新但训练目标也不改善：查目标方向、输入表示与优化状态。
- 训练目标改善而验证结构变差：查泛化、目标不一致、先验错误或过度修正。
- 曲线仍在明显学习：可提出更充分预算，但不能保证延长必涨。

这些只是待验证分支，不能据单张曲线直接判定唯一原因。

## 四、没有历史轨迹怎么办：补观测，而不是编造

1. 有 history、中间 checkpoint 与 optimizer 状态时，优先恢复真实证据。
2. 只有初始化/最终权重时，只报告累计差异，不能画出不存在的逐step轨迹。
3. 当前 checkpoint 上的新诊断，要写“当前状态诊断”；缺少原随机数、采样序列或 optimizer 状态的回放，要写“近似重演”，不能声称精确复现历史。
4. 必要时在隔离副本上做短程训练回放，补齐真实参数更新轨迹；不要因上一版只读限制永远不采集动态证据。
5. instrumentation 不能污染实验：保护 RNG、模型参数与 buffers、optimizer、scheduler、AMP scaler；额外梯度计算不重复累积进正常梯度；诊断 forward 不偷偷更新归一化统计。
6. 每步保留轻量标量/模块统计，仅在预定检查点保存必要张量摘要与快照。不逐步保存全模型、全特征或全 Jacobian，不为日志耗尽显存和磁盘。
7. 新增日志尽量支持统一 runner、相同执行模式，确认“加日志前后”的等价性；不要为了统计改变 loss、数据顺序或有效训练量。

## 五、把内部变化与最终错误连起来

不能只得到“某层更新较小”，然后直接建议调大学习率。

需要形成这样的证据链：

`具体实现/配置 → 信息或梯度路径异常 → 参数实际变化异常 → 特征/预测的对应改变 → 标准指标与错误病例的对应表现`

TSRS：对齐新增/删除的预测像素与真实前景、边界，检查是否通过减少前景换取部分边界改善；不得仅凭 Precision 上升和 Recall 下降就断言整体收缩。

RAM：比较每个候选自身 backbone 输出与自身 final 输出，按成员检查正确恢复、错误新增、漏失和轮廓改变；A 的 logits 不能冒充 C/D 的修正前 logits。

先验质量要在基线已分对和实际犯错的位置分别看。平均先验 BCE 较好不代表它对剩余错误有帮助；不能预设“生成器可用，原因一定在下游”。同样不能预设“强基线已经没有可改进空间”。

诊断分组和图片选择规则提前固定，包含改善和恶化病例；GT 只用于监督与离线分析，不进入正常推理。标准性能评价仍是最终依据，但不能单凭最后分数倒推机制。

## 六、先定位，再选择修改；不要一次更换整套方案

最多优先排序3个瓶颈，每项包含：

`现象 | 代码/日志/张量证据 | 候选机制 | 替代解释 | 最小验证 | 支持信号 | 反驳信号 | 证据级别`

证据级别区分：
- 已复现的实现缺陷；
- 内部证据一致但尚未通过性能对照验证的解释；
- 未检验猜测。

即使确认一个 bug，也不能自动说它解释全部历史收益不足。主因可以是多个因素交互；证据不够就写目前无法确定唯一主因，并给出下一项最小验证，不能编一个确定答案。

针对最优先问题，修改类别可以是：
- 训练参数或状态：LR组、调度、冻结范围、optimizer登记/恢复、训练暴露；
- 先验表示：目标定义、归一化、尺度、信息质量、成员上下文；
- 先验接入：输入、特征层、skip、decoder、门控或输出位置；
- loss：目标方向、作用层、分母、局部权重、preserve/几何约束、routing/cap。

先给出可解释的最小差异，不同时改结构、LR、训练时长、目标和评价。可以修复多个确定的机械性bug，但必须单独记录；修复包的收益不能单独归给其中一个未隔离因素。

若怀疑两个因素交互，先解释为什么单因素不足，再申请一个小型因子对照；不能直接扩成几十组搜索。

## 七、受控验证不能省略

针对优先假设，先写一对 reference / variant：
- 相同初始化，包括适用的 optimizer/scheduler/scaler 状态；相同数据、随机序列、增强及评价。
- 唯一变化是什么，哪些参数/行为因此必然改变。
- 如果改接入位置，尽量控制模块容量、目标和训练协议；不可同时加大网络又声称纯位置收益。
- 如果改 LR，其他训练规则不变；如果研究训练充分性，就同时延长可比 reference，不能拿多训练的新模型对旧200步 A 归因。
- 先验扰动敏感性与单步分叉只是诊断，最终效果仍须匹配训练对照。
- 对 fresh 与 mature 分支分别使用合法参照，不能错配整个 backbone 和 refiner 后下结论。
- 所有相同seed对照也要核对数据序列；新增模块初始化消耗 RNG 不得悄悄改变采样。

验证分两层：
1. 机械层：预期的信息路径/更新/局部行为是否按假设改变。
2. 效果层：相同验证集上的标准指标是否改善，有何副作用。

如果只完成第一层，不能宣布效果问题已经解决。若没有改善，如实否定或缩小该解释，保留reference和负结果，不追改阈值救结果。

## 八、评价只使用可靠标准，不替模型挑分数

TSRS沿已核验的 Dice/IoU、Precision/Recall、Boundary IoU、NSD/Surface Dice、HD95/ASSD。RAM沿整体/成员 DSC、NSD、VOE、MSD、RAVD，以及有来源的骨对重叠DSC/NSD；MSD具体定义和Pair应用如实说明。

从最终分割计算，不用先验图自身指标替代。空预测、距离失败、成员/骨对分母、像素/物理单位、聚合方式固定并记录；IoU与mIoU、全overlap图与具体骨对不能混称。

旧gap/merge/成员增删计数只用于诊断，不新增自定义主指标或加权结构总分。不修改旧结果；标准实现若与旧协议不一致，同一预测另列结果，不将分数口径变化算成模型提升。

小负差不自动等于崩溃或浮点误差；单seed短回放不能证明稳定提升。后续正式结论需要公平预算、关键比较多seed，以及可核验的逐病例数据。没有独立患者信息就说明，不伪造统计显著性。

## 九、本轮可直接做什么，什么时候必须停

本轮允许：
- 本地定向证据审计、隔离诊断脚本、必要标准指标重算、固定train/val推理；
- 内部hook、loss/梯度/optimizer状态追踪；在备份副本上的必要补丁与单测；
- 为补轨迹和验证一个优先问题，进行有界的短程回放与最多一对 reference/variant 小对照。

开始任何新增真实optimizer更新前，先写并呈报 `DIAGNOSTIC_RUN_LOCK.json`：目的、参考版本、唯一变量、数据/源码/配置/权重哈希、步数、采样、日志频率、选模与标准评价、GPU/内存/磁盘、时间上限和退出条件。

默认本轮安全上限：新增真实训练累计不超过 **2 GPU小时**，只围绕 **一个优先假设**，先用 **一个seed**；回放与reference/variant计入同一上限，不叠加旧额度。先用实际完整step耗时确定能做多少更新，不凭文件里的历史耗时猜算力。这个上限只是限制投入，不是收敛或成功判据。

若预计超出该上限、需要全量长训/更多对照/新算力/付费操作，先给出测时依据和预算，等待确认。当前环境有更严格安全/权限限制时仍遵守。不要中断已有任务腾资源，不扫描或写入未授权的根外目录，不覆盖checkpoint或原始数据。

不是要求必须耗满预算：现有证据充分时少做；若现有预算不足以验证学习充分性，明确给出仍缺多少证据，不从短回放推断最终收益，也不自动续训。

## 十、最终交付：必须有真实轨迹和可执行结论

沿用本地适合的文件组织，不为名称重建整个项目。至少交付：

1. `DIAGNOSIS_AND_ACTION.md`
   - 当前效果是否达到目标，哪些不能比较；
   - 最多3个主要瓶颈及证据级别；
   - 已改什么、为什么、实际验证支持还是反驳；
   - 仍未知什么；下一项唯一优先动作与预算。

2. `RUN_CONFIG_AND_RESULT_DIFF.csv`
   - 关键run的初始化、实际训练参数、有效更新、数据/评价差异及原始指标。

3. `TRAINING_TRACE.jsonl` 或等价真实日志
   - step、case、参数组、loss、各阶段梯度、LR/optimizer状态、实际更新量与激活/先验摘要；
   - 标记历史记录、精确恢复、近似回放或当前状态新诊断；没有的数据写缺失，不能补造。

4. 最小代码diff、测试结果与 `DIAGNOSTIC_RUN_LOCK.json`
   - 若做了受控验证，附reference/variant的同口径结果与逐例数据；
   - 未训练或未充分验证时明确NOT_RUN/INCONCLUSIVE，不用通过单测冒充指标提升。

报告不要用“大概是学习率”“建议多训”“统一框架更合理”结束，也不要只交新的方案文档。
