# RAM 骨重叠先验 O 与原始 NPY 标签核对

日期：2026-09-28。范围是实际数据目录 `G:/gutou/RAM-W600` 的 train425 / val69；本轮只读审计，**test 未读取、模型与标签均未更新**。

## 直接回答

没有发现 `.npy` 把重叠标错位置、图像/标签左右翻转不一致，或 O 图整体错位。**“先验传达错误位置”需要更准确地表述为：当前图像生成器 O 能找出较明显的重叠区域，却在 C0 真正漏检的重叠成员位置给出偏低概率，同时在一部分单骨前景上给出偏高概率。**准确的标签只是监督目标；O 是一个另行训练、只看 X 光图像的估计结果，不会自动等于标签。

train425/val69 共 494 份 `.npy` 均为 `(14,H,W)`、`int8`、仅含 0/1；每份与同名 BMP 宽高相同，14 个通道均有标注。真实重叠按 `sum(14 个成员标签) >= 2` 构造，而 O 生成器只输出一张“这里可能重叠”的概率图，不输出具体是哪两块骨。`_R` 样本的图像和标签同时水平翻转，再做逐图标准化、右下补零；O 的输入/输出保持同一原生坐标。val69 的真实重叠有 1,120,306 个唯一像素。文件结构与转换核对通过**不等于临床逐像素标注绝对无争议**，但目前没有标签文件损坏或坐标错配的证据。

## O 在哪里失效

| 位置，val69 | O 均值 | O≥0.5 的比例 |
|---|---:|---:|
| 所有真实重叠像素 | 0.579 | 60.33% |
| 真实重叠中非 C0-H0 的像素 | 0.601 | 63.38% |
| C0 真正漏检的重叠成员 H0，71,335 个成员位置 | **0.245** | **15.07%** |
| 单骨前景像素 | 0.035 | 1.23% |
| 背景像素 | 0.00068 | 0.0013% |

O≥0.5 时全局检测真实重叠的 precision 为 **82.18%**、recall 为 **60.33%**，与原生成器报告相符；但它只覆盖 **10,750/71,335** 个 H0 成员位置。错误高亮主要落在**单骨前景 146,391 个像素**，背景只有 186 个。因而它不是随机照亮背景，而是容易把部分单骨/相邻骨区域也看成重叠；而对真正需要补回第二成员的困难点又偏保守。train425 重复了同一现象：全部真实重叠召回 59.83%，H0 成员位置仅 **33,559/228,695=14.67%** 被 O≥0.5 覆盖。

降低 O 阈值不能免费解决：在 val 上阈值从 0.5 降至 0.2，H0 被高亮成员位置从 10,750 增至约 30,311，但被高亮的**单骨**像素也从 146,391 增至约 625,358。这是先验候选的负例代价，不是分割模型的最终 FP，不能混写。

## 是坐标偏移、缩图吃掉标签，还是模型没有学好？

**没有全局坐标偏移证据。**在 val69 对 O 二值图测试水平/垂直各 ±4 原图像素平移，整体重叠 Dice 最佳仍是 `(dy,dx)=(0,0)`。左右手的 H0 O 均值分别约 0.242/0.249，也未显示一侧翻转失败。H0 原位置仅 15.1% 与 O≥0.5 重合，但 3、7、15 像素邻域内出现高 O 的比例依次为 32.9%、55.8%、80.4%。这支持“高信号常在附近、困难位置局部覆盖不足”，**不等于**应把整张 O 图平移 7 或 15 像素。

**困难位置偏向真实重叠边缘，但不能只归咎于分辨率。**val H0 距真实重叠外边界的内部距离中位数为约 2.83 px，其余真实重叠约 4.47 px；train 为 1.41 px 对 4.24 px。因此 192×192 输入确实可能削弱局部边缘线索。然而，用训练脚本完全相同的 `area` 将**准确 GT** 缩到 192×192，再双线性还原，val 的真实重叠 Dice 仍为 **0.979711**、recall **97.32%**。在 H0 成员位置，这张重建的软目标有 **93.42%** 仍≥0.5（train 89.26%），实际 O 却只有 15.07%（train 14.67%）。即使在离重叠边界 >5 px 的 val H0，软目标几乎为 1，O≥0.5 也只有 26.28%。**标签没有在缩放监督中大面积消失；是生成器没有在这些困难图像位置输出足够强的响应。**软目标重建不是图像生成器能力的理论上界，不能据此断言 192 图像分辨率无影响。

`EXT_` 前缀不是完全未见的测试域：train 中已有该类样本。它们通常是 650/720 尺寸，缩到 192 时比例不同；val 的 14 个 `EXT_` 样本包含 25,441/71,335 个 H0 成员位置。其真实重叠 O≥0.5 召回为约 48.1%，普通前缀 55 例约 64.8%；H0 的 O 均值 0.204 对 0.268。这个分层差异需要查明图像形态/训练覆盖/误差分布，不能直接称标签错误。

**还有一个小的推理口径不一致，但不是主因。**生成器原验证用 `上采样(sigmoid(192 logits))`，下游实际用 `sigmoid(上采样(192 logits))`。对完整 val 有效像素，平均概率差约 0.000809；H0≥0.5 分别为 **10,736** 与 **10,750**，只有 78 个 H0 成员位置跨过阈值。因此应在未来评价中统一这个顺序，但它无法解释其余约 6 万个未高亮的 H0。

## 为什么标签准确仍会出现这种情况

O 的训练目标是所有重叠像素的普通 BCE，在 192×192 图像上学一张**不分骨成员**的二值概率图，没有针对 C0 的困难漏检作权重或成员监督。全局真重叠像素中 H0 仅占一小部分；模型能靠较明显的大片重叠取得不错的总体 precision，却不给这些边缘/困难点足够概率。既有原图强度审计还显示：虽然总体重叠平均更亮，在严格匹配的 H0 对照里，原始灰度 AUC 约 **0.501**，单凭“更白”几乎区分不了；O 的匹配 AUC 约 **0.841**，说明它有一些可用的结构信息，但远未达到可直接补回成员的程度。即便 O 完美找出重叠区域，单张标量图仍不能说明 14 个标签中**缺的是哪一个成员**。

因此，已经证实的是“标签和坐标没有发现硬错误；O 在 H0 低响应、单骨处有误高亮；简单换接入层在先前 test124 对照中未改善”。**尚未证明唯一成因**是 192 图像分辨率、BCE 类别不平衡、样本形态差异、生成器容量或成员身份缺失中的哪一个，不能把某一项猜测写成定论。

## 下一项最小验证

先保持 nnU-Net/R332 不变，只针对**先验生成器**做一对 train425 内部匹配对照：相同生成器起点、图像、分辨率、优化器、更新数，一组沿用原 BCE，另一组仅对训练集固定 C0-H0 的真实正重叠位置增加监督权重；不能把 H0 或 GT 当作生成器推理输入。验证时除了总体 overlap precision/recall，预先固定同等**单骨误高亮预算**，比较 val69 H0 覆盖及 `EXT_`/普通病例的逐例代价。若不能在误高亮受控下改善 H0，就先别再把同一张 O 图送入分割模型；若改善，再从同一 R332 起点做一对分割训练。**本轮没有执行这对新训练，也没有使用 test 调整 O。**
